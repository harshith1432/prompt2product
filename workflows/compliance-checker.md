# Workflow: Security & Legal Regulatory Intelligence

This workflow ensures that every application generated by the Enterprise Orchestrator adheres to enterprise-grade security standards (**OWASP Top 10**) and international data privacy laws (**DPDP Act 2023**, **GDPR**, **CCPA**).

---

## 1. Security Architecture: OWASP Top 10 Hardening

Every generated project must implement concrete defenses against the OWASP Top 10:

### 1. A01: Broken Access Control
* Enforce server-side role validation for all sensitive operations (admin panels, order cancellation).
* Prevent IDOR (Insecure Direct Object References): Validate that a user can only query and mutate their own cart, orders, and addresses.

### 2. A02: Cryptographic Failures
* Use modern password hashing (e.g., `bcrypt` with salt rounds >= 10 or `Argon2id`).
* Never store plain text payment credentials; use simulated tokenized payment references.
* Enforce HTTPS/HSTS and TLS-only session cookies with `Secure`, `HttpOnly`, and `SameSite=Strict`.

### 3. A03: Injection (SQL / NoSQL / Command)
* Use parameterized queries or safe ORM mappings (Prisma, Drizzle, TypeORM).
* Strictly avoid dynamic query string concatenation.
* Sanitize user-provided search queries and rich text fields using schema validation (e.g., `zod` or `joi`).

### 4. A04: Insecure Design
* Enforce rate limiting on authentication routes (login, registration, forgot password) and checkout endpoints.
* Implement anti-automation / bot defense thresholds for cart spamming.

### 5. A05: Security Misconfiguration
* Implement security headers via middleware (e.g., `helmet`):
  * Content-Security-Policy (CSP) restricting script/object sources.
  * X-Frame-Options: `DENY` or `SAMEORIGIN`.
  * X-Content-Type-Options: `nosniff`.
  * Strict-Transport-Security (HSTS).
  * Explicit CORS whitelist (prevent wildcard `*` with credentials).

### 6. A07: Identification & Authentication Failures
* Session management with automatic expiration and re-authentication for sensitive actions.
* Multi-factor authentication (MFA) hooks or email verification simulation.

### 7. A08: Software and Data Integrity Failures
* Validate package dependencies against known CVEs (`pnpm audit` / `npm audit`).
* Verify integrity of third-party assets and scripts.

### 8. A09: Security Logging & Monitoring
* Log security events (failed logins, privilege escalation attempts, password resets) with timestamps, IP masking, and user IDs.
* Prevent sensitive PII (passwords, card tokens) from being written to log files.

## 2. Legal Regulatory Compliance (DPDP Act 2023 & GDPR/CCPA)

### 1. India's Digital Personal Data Protection (DPDP) Act 2023
* **Notice & Explicit Consent:** Present a plain-language, bilingual/accessible consent notice prior to collecting personal data (name, email, phone, shipping address).
* **Purpose Limitation:** Collect data strictly necessary for order processing, shipping, and account management.
* **Consent Manager & Withdrawal:** Provide users with an accessible UI toggle in their profile to review, withdraw, or modify consent at any time.
* **Right to Erasure & Correction:** Provide a dedicated API endpoint (`/api/user/data/erasure`) and UI button allowing users to request complete account and data deletion.
* **Data Protection Board & Grievance Redressal:** Display a clear Grievance Officer contact and redressal procedure in the footer and Privacy Policy.
* **Children's Data Protection:** Prohibit behavioral tracking or profiling on users identified as minors.

### 2. GDPR & CCPA Compliance
* **Cookie Consent Banner:** Categorized toggles (Strictly Necessary, Functional, Analytics, Marketing) with "Accept All", "Reject Non-Essential", and "Preferences".
* **Do Not Sell or Share My Personal Information:** Accessible CCPA link in the footer.
* **Data Portability:** Endpoint allowing users to download their personal data in machine-readable JSON format (`/api/user/data/export`).

## 3. Compliance Acceptance Checklist

The Security & Compliance Subagent must verify that the following deliverables exist before approving the build:

- [ ] `middleware/securityHeaders.ts` (Helmet, CSP, CORS configured)
- [ ] `middleware/rateLimiter.ts` (Rate limiting on `/api/auth` and `/api/checkout`)
- [ ] `components/legal/CookieConsentBanner.tsx` (Granular GDPR/DPDP consent)
- [ ] `components/legal/PrivacyPolicyModal.tsx` (DPDP Act 2023 compliant terms)
- [ ] `components/profile/DataPrivacySettings.tsx` (Consent withdrawal and data erasure request buttons)
- [ ] `routes/privacy.routes.ts` (`/export` and `/erasure` functional endpoints)
